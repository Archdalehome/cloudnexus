# 📝 订单管理系统（Cloudflare Workers + KV）

一个极简的**订单管理系统**，部署在 Cloudflare Workers 上，使用 Cloudflare KV 存储数据，**无需数据库**。

## ✨ 功能

- **登录页**：用户名 + 密码登录；点击「**新帐户注册**」可申请为**团队用户**（**试用期无期限**）
  - **注册邮箱确认码（必须先确认）**：团队账号注册时，系统会先向「**注册时填写的邮箱**」发送 **6 位邮箱确认码**（**10 分钟有效**）；
    注册人**登录时必须先输入邮件中的确认码完成邮箱确认，确认通过后才能正常登录**（注册成功**不再自动登录**）。
    确认码可在登录页点「**重新发送确认码**」重发（需填写该账号的登录密码；**1 分钟内不重复发送、1 小时最多 5 次**），
    **连错 5 次即失效**、需重新获取；已确认的账号（含升级前的历史账号）登录方式不变。
- **超级管理员控制台**（`/admin`）：仅管理团队用户 —— **开通 / 停用 / 开通或续费（升级为专业版） / 重置密码 / 备注信息**（含团队提交的**订阅申请 / 续费申请**处理），**停用后可「删除」彻底清除该团队及其成员与全部数据**，顶栏另有「**重置密码**」按钮用于**重置超级管理员自己的登录密码**（无需原密码，输入新密码 + 确认新密码即可；见 `/api/admin/password`），可在「系统设置」中修改全局「**网站名称**」「**是否允许新用户注册**」（关闭后登录页不显示「新帐户注册」，注册接口也会拒绝）与「**忘记密码联系邮箱**」（登录页显示的客服邮箱，留空则不显示该提示）与「**网站图标链接**」（浏览器标签页图标，填图片链接即可，留空用默认）与「**广告代码**」（**试用版页面顶部的广告位**：HTM​L / JS 片段，≤3000 字符，**订阅专业版后自动移除**，留空表示不插入广告），并可配置**「邮件设置」**（注册邮箱确认码的发件服务：**QQ 邮箱 SMTP 账号 + 授权码（推荐）** / SMTP 服务器与端口 / 发件邮箱 / 发件人名称 / Resend API Key / 发送测试邮件 / 调试模式，以及**订阅 / 续费申请邮件**：管理员提醒邮箱 + 自定义文字说明 + 最多 3 个**收款二维码图片**，团队提交申请时会自动发给申请人并抄送管理员）
- **待办事件页**：
  - 🏠 **团队账号本人（团队管理员）登录后的首页 = 「系统介绍 + 使用说明」（已取消订单列表功能）**：不显示订单列表、也不显示「添加新订单」录入区；页面**按账号版本分别编写两套内容**（见下方说明），并含固定的 **5 大板块** —— 系统介绍、角色与权限、订单状态与关键操作、成员权限开关（含 7 项权限默认值）、**分步使用说明**；顶栏的「团队设置 / 成员管理 / 生产方管理 / 客户管理 / 订阅（续费） / 修改密码 / 退出」与站内消息角标全部保留
    - **🆓 试用版内容**：版本标签（绿色「试用版」）+ 本版本功能说明（**无限期试用**、**成员 2 / 生产方 1 / 客户 1** 上限、**页面顶部广告位**、**没有生产方时可直接改为「进行中」**、订阅升级流程）+ **实时的「已用 / 上限」**（成员 / 生产方 / 客户）+ 试用版 8 步使用说明与提示
    - **🔷 订阅版（专业版）内容**：版本标签（蓝色「订阅版」）+ 本版本功能说明（**有效期与剩余天数**（实时显示）、**成员 / 生产方 / 客户不限**、**无广告位**、**改为「进行中」必须先指定生产方**、到期回落试用与续费流程）+ 订阅版 8 步使用说明与提示
    - **版本自动切换**：订阅 / 续费成为专业版后（或订阅到期回落为试用）页面自动切换到对应内容（服务端按当前订阅状态渲染首屏，前端每 60 秒同步一次，刷新页面立即生效）；`GET /api/todos` 对团队账号同样返回 403（**即使直接调用接口也不会返回订单**）
  - **团队账号本人**在**左上角版本徽章右侧**可见「**订阅**」/「**续费**」按钮：试用账号（未订阅或订阅已到期）显示蓝底「**订阅**」，专业版**剩余天数不足 30 天**显示「**续费**」（点击选择套餐并提交申请，由超级管理员开通）
  - **试用版（未订阅 / 订阅已到期）功能与专业版基本相同**，仅保留**数量限制**：**成员最多 2 个、生产方最多 1 个、客户最多 1 个**（成员管理 / 生产方管理 / 客户管理**都有入口**，达到上限时「添加」按钮置灰并提示订阅可解除限制），**页面顶部还会显示「广告位」**（广告代码由超级管理员在控制台「系统设置」中维护）；**订阅为专业版后：数量限制解除 + 广告位移除**。**试用版与专业版一致：团队账号本人不录入订单**（订单由成员录入 —— 先在「成员管理」添加成员、在「可录入订单客户列表」中为其分配客户），且**不显示订单列表**（首页为「系统介绍 + 使用说明」，见上条）
  - **左上角统一显示「所属团队名称」**（团队成员 / 生产方 / 客户与团队账号本人看到的名称一致）；**名称由服务端渲染，首屏即为团队名**（不会先闪一下默认站名再切换）；**版本类型与有效期徽章只对团队账号本人显示**
  - **订单列表筛选行**（列表上方「筛选」一行，**所有能看到订单列表的角色都有**）：两项筛选可**单选或双选** ——
    - **客户选择**：下拉选项为**当前账号授权可以显示的客户**（由服务端 `GET /api/filter-customers` 按角色 / 可见范围返回：总经理 / 部门主管为「客户管理」全部客户 + 本团队订单中出现过的客户；普通成员为「可查看客户列表」+ 自己订单中的客户（可查看全部订单时同总经理）；业务主管 / 生产部 / 生产方为其可见订单中的客户；客户账号仅本客户；**团队账号本人已取消订单列表 → 该接口返回 403**），另有首项「**全部客户**」；**只影响显示，不改变订单可见范围**；
    - **状态选择**：`进行中`（**默认**）/ `待确认` / `已完成` / `全部状态`；
    - **默认视图**：**全部客户 + 进行中** —— 即「原授权可见订单中状态为『进行中』的订单」；要查看**其他状态**的订单需在筛选行选择对应状态（或「全部状态」）；
    - 筛选行右侧显示「**显示 X / Y 条**」（X = 当前筛选后条数，Y = 本账号授权可查看条数）；点「**重置**」恢复默认（全部客户 + 进行中）；筛选后无结果时会提示「没有符合筛选条件的订单（本账号可查看 N 条）」；
    - 其他联动：**新录入的订单为「待确认」** —— 若当前筛选会把它隐藏，录入成功后自动切到「待确认」并提示「新订单已录入（状态：待确认）」；点站内消息里的 @ 提醒时，若对应订单被筛选条件隐藏，会**自动切到「全部客户 + 全部状态」**后展开该订单
  - **「状态」与「生产方」都按普通形式显示，点击即可修改（不再是下拉菜单）**：订单行**最左侧的状态**始终显示为彩色徽章（🟠 待确认 / 🔵 进行中 / 🟢 已完成）；**待确认阶段**的「生产方」也显示为**普通文本标签**（未指定时橙色「选择生产方」，已指定时显示生产方名称）。**有权限的用户（总经理 / 部门主管 / 权限5「是否可以更新订单状态」= 有）点击该徽章 / 标签**即**就地变为下拉选择**（浏览器支持时自动展开原生选项列表），选好立即保存并恢复为普通显示；**失焦未改或保存失败则原样换回**；由于只替换该元素（不整表重绘），**编辑过程中已展开的订单保持展开**。无权限的用户：状态徽章为**只读**（点击无反应），且不显示生产方控件
  - 折叠显示待办事项，仅显示「主题」和「添加日期」
  - 每个待办固定**一行**显示（不换行）；宽度不足时按优先级隐藏次要标签（添加日期 → 所有者 → 金额 → 出货日期），**生产方标签（生产方用户名·性质）、订单号（PO#）与订单号右侧的「回形针」图标（脱敏订单文件链接）始终可见**，PO# 过长时以省略号收尾；**交期始终可见** —— 手机上位置不够时自动只显示「**月/日**」（不显示年份），同样保持一行不换行；**「客户」在手机上也不再隐藏**（窄屏时允许收缩、过长以省略号收尾）
  - **录入者标签**（订单行上的灰色小标签）：总经理 / 部门主管 / 观察类角色在能看到**他人**订单时显示录入者（自己的订单不显示）；**普通成员的清单里每条订单都显示录入者**（**含自己的订单**）
  - 订单行右侧标签显示为「**生产方用户名·生产方性质**」（如「张三·自产」/「李四·外购」）；**性质由团队管理员在「生产方管理」中手动填写**（最多 3 个中文字符或 6 个英文字符），悬浮可见「生产方：…｜性质：…」；**未填写「采购文件链接」时标签为黄色色块**（提示需补采购文件），已填写时为**灰色**中性色；**业务主管 / 生产部**的待办同样显示
  - **补填采购文件链接**：缺链接的黄色「生产方用户名·性质」标签（如「张三·自产」），**有权限3「是否可以下生产订单」的成员可直接点击**（⚠️ 团队账号本人已取消订单列表；**权限5「是否可以更新订单状态」= 有** 的成员等同于已授权；普通成员由团队管理员在「成员管理」的成员列表中单独开关，**默认「无」**），弹窗填写 `http://` / `https://` 链接并保存（不限订单状态；只能补「当前为空」的链接，已有链接仍需有权限的成员在「待确认」阶段修改）；无该权限的成员点击无反应（标签仅作提示）
  - **脱敏订单文件链接（订单号右侧的「回形针」图标）**：**所有登录用户**的订单行上，订单号右侧都显示「回形针」图标 ——
    - **已有链接**：图标**正常着色（蓝色）**并指向该链接，点击即在新标签页打开该**脱敏订单文件**（不会触发展开/折叠）；此时图标**只提供打开功能**，**不能再添加 / 修改链接**；
    - **暂无链接**：图标为**浅灰色** —— 有权限6「**是否可以下脱敏订单**」的成员（⚠️ 团队账号本人已取消订单列表；普通成员由团队管理员在「成员管理」的成员列表中单独开关，**默认「无」**；⚠️ 权限5 不含该权限）点击可弹窗填写 `http://` / `https://` 链接并保存（不限订单状态；只能补「当前为空」的链接）；**无该权限的用户**灰图标**仅作提示，点击无反应**；
    - 响应式：PO# 过长时订单号以省略号收尾，**回形针图标不会被挤掉**。
  - **出货日期（「交期」区块右侧的灰色区块，长度与交期一致）**：**所有登录用户**的订单行上，**交期右侧**都有一个同长度的灰色区块 ——
    - **未填写**：显示为**灰色空白区块**（宽度与交期区块一致，用不可见占位符撑开）；有权限7「**是否可以添加出货日期**」的成员（⚠️ 团队账号本人已取消订单列表；普通成员由团队管理员在「成员管理」的成员列表中单独开关，**默认「无」**；⚠️ 权限5 不含该权限）点击可弹窗选择**出货日期**并保存（不限订单状态；只能为「当前为空」的订单添加）；**无该权限的用户不能点击**（区块仅作占位显示）；
    - **已填写**：区块内显示**出货日期**（灰色日期区块）—— **不能再被点击重复添加**（有权限者同样不能重复添加）；
    - 响应式：窄屏下该区块比「交期」更早隐藏，保证交期仍可见。
  - 金额标签为**灰色**（中性色，避免与交期的绿/黄/红混淆；观察类用户不显示金额）
  - **总经理 / 部门主管（历史账号）与权限5 成员**可**直接点击**「待确认」待办上的**交期 / 金额**标签，打开弹窗修改 **PO#（主题）/ 交期 / 金额 / 订单文件链接**（进入「进行中 / 已完成」后不可再改）；⚠️ **团队账号本人已取消订单列表**，该操作现由上述成员完成
  - 新增订单**一行内**依次为：**客户**（下拉，首项显示「客户」；选项即该成员「可录入订单客户列表」中被分配的客户）、**订单号**、**交期**、**币种**（下拉：美元 / 人民币）、**金额**、**订单文件链接**、**「生产方选择」下拉**（位于订单文件链接右侧；**仅权限「可选生产方」被授权的成员可见**，选项为被授权的生产方，可给本订单直接指定生产方；默认「无」时该下拉不显示）与「添加」按钮。**团队账号本人（团队管理员）不显示该录入区**（**试用版与专业版一致**：订单由成员录入，接口同样拦截）。**录入区由服务端在渲染页面时按当前用户权限决定是否输出（无权限者首次响应即隐藏，登录后不会闪现）**。**手机 / Pad** 上该行自动改为**单列堆叠**（币种 + 金额并排一行），按钮整行显示
  - 录入订单时可填写**订单文件链接**（须以 `http://` 或 `https://` 开头，可留空）并选择**币种**（**美元 / 人民币**，默认美元；金额标签按币种显示 `$` / `¥`，历史数据按美元显示）。**「采购文件链接」不在录入表单里填写**，而是录入后在订单行上通过黄色「自产单 / 外购单」标签补填（见上条）。点击 PO# 打开的文件：**团队管理员 / 生产方 / 客户** 打开**订单文件链接**；**普通成员**按权限2「**是否可以查看客户订单**」开关（**默认「无」**）；**部门主管**（历史账号）按「是否可查看客户订单」开关（默认「是」）；业务主管 / 生产部 / 总经理的 PO# 始终为纯文本、不可点击。**已填采购文件链接**的**自产单 / 外购单标签可直接点击打开该订单的采购文件**：团队管理员 / 总经理、**普通成员**（按权限4「**是否可以查看生产订单**」开关，**默认「无」**）、**部门主管**（历史账号，按「是否可查看采购订单」开关，默认「是」）均可点击
  - 交期标签只显示日期（如 `2026-09-30`）；**待确认 / 进行中 / 已完成**三种状态都按交期着色：已到期/逾期=红、剩余 2 周内=黄、剩余超过 2 周=绿（三种状态配色一致）
  - 点击主题后下拉展开详情（参考 Notion 展示方式）
  - 交期输入框空值时显示自绘提示 `yyyy/mm/dd`（不受浏览器语言影响；有值或聚焦时显示原生日期，Firefox 用原生 `placeholder`）
  - **备注为追加式**：任何用户（含业务主管）都可在待办下添加备注，备注记录作者与时间，**添加后不可删除**
  - **站内消息（@提及）**：备注输入框中输入 **`@`** 会自动列出**本团队人员**（**各成员**，**不含团队管理员账号、也不含自己**），点击即插入 `@用户名`；提交后备注里的 @提及 **高亮显示**，被 @ 的成员会在**登录名左侧**看到角标（未读 @ 次数：**红色**数字，**超过 9 显示「9+」**；未读为 0 但仍有历史提醒时显示**灰色「0」**，仍可点开查看历史）；点角标可查看消息明细：点某条即标记已读并关闭清单，每条右上角的「未读」勾选框可将该条**重新标记为未读**（红点数量自动 +1）
  - 支持标记完成 / 删除待办
  - **「已完成」折叠加载**：为免已完成待办过多拖慢首屏，**默认只显示最新 5 条**，底部出现「**加载更多（还有 N 条）**」按钮，**每点一次再多显示 20 条**；标题「已完成 (N)」始终显示总数
  - **「手机 / Pad 自适应」**：窄屏下顶栏按钮自动换行、内容留白与订单展开区缩进收紧、**订单录入区改为单列堆叠**、订单行按可用宽度**自动隐藏次要信息**（宽 → 窄依次隐藏 日期 / 录入者 / 金额 / 出货日期，PO# 与「生产方用户名·性质」标签始终可见；**交期始终显示**，位置不够时只显示「月/日」；⚠️ **手机端「客户」不再隐藏**，始终显示）、弹窗贴边且内容超高时内部滚动、表单控件字号在手机上为 16px（iOS 聚焦时不会自动放大页面）；成员管理与各弹窗在手机上改为上下堆叠

### 🧾 团队用户（新帐户注册）使用流程

1. 打开登录页，点击 **「新帐户注册」**，填写 **团队名称 / 登录用户名 / 邮箱（必填，用于接收确认码） / 密码 / 确认密码**（联系人、申请说明选填），提交。
   > ℹ️ 若超级管理员在「系统设置」中勾选了「不允许新用户注册」，登录页**不会显示「新帐户注册」按钮**（注册接口也会拒绝）。
2. 提交后系统**立即向该邮箱发送 6 位邮箱确认码**（**10 分钟有效**），页面切到「**邮箱确认**」卡片（**不会直接登录**）：
   - 到邮箱查收确认码 → 在卡片中输入 **6 位确认码** → 点「**确认并登录**」；确认通过后自动进入待办页；
   - **没收到邮件 / 确认码已过期** → 点「**重新发送确认码**」（会校验该账号的登录密码；**1 分钟内不重复发送、1 小时最多 5 次**）；
   - 确认码**连错 5 次即失效**，需重新发送后再输入；
   - 之后再登录只需 **用户名 + 密码**；若账号尚未确认邮箱，登录时系统会再次要求输入确认码（并自动补发一封，10 分钟内已有的确认码不重复发送）。
3. 邮箱确认通过后账号即为**试用账号**：
   - **试用期无期限**（顶栏显示「**试用中（无期限，数量受限…）**」，不会到期，也不会因此被阻止登录）；
   - **功能与专业版基本相同**：成员管理 / 生产方管理 / 客户管理**都有入口**，可添加成员、生产方、客户并维护订单状态；**仅数量受限**（**成员最多 2 个、生产方最多 1 个、客户最多 1 个** —— 达到上限时「添加」按钮置灰并提示订阅可解除限制）；
   - **页面顶部显示广告位**：广告代码由超级管理员在控制台「系统设置」中维护（未配置则不显示）；
   - **不录入订单、也不显示订单列表（与专业版一致）**：登录后的**首页是「系统介绍 + 使用说明」**（按试用版 / 订阅版分别展示：系统介绍、角色与权限、订单状态与关键操作、成员权限开关、分步使用说明）—— **没有订单列表、也没有「添加新订单」录入区**（`GET/POST /api/todos` 对团队账号都会拦截）。请先在「成员管理」中添加成员、在「可录入订单客户列表」中为其分配客户，再由成员登录录入订单；订单的确认（改为「进行中」）、指定生产方、补填采购文件 / 脱敏订单文件 / 出货日期、备注等全部由成员完成（**试用团队没有生产方时可直接把订单状态改为「进行中」**，已添加生产方后需先指定生产方）。
4. 需要**解除数量限制 / 移除页面广告位**时，点击顶栏「**订阅**」→ 选择套餐 → 「提交订阅申请」；**超级管理员开通后即成为专业版**（数量不限 + 广告位移除，并继续使用全部功能）。
5. 被停用时无法登录，提示「该账户已被停用，请联系超级管理员开通」；再次「开通」即恢复。
6. **超级管理员**（`admin / admin`）登录后进入 **团队用户管理控制台**（`/admin`），可对每个团队执行：
   - **停用 / 开通**：停用后该团队及其所有成员均无法登录（已登录的会话也会立即失效）；再次开通即恢复。
   - **开通 / 续费**：输入天数或点套餐快捷按钮（1 个月 30 / 1 年 365 / 3 年 1095 / 5 年 1825 天），从「当前时间」与「原到期时间」中较晚者起顺延；**开通后该团队即为专业版**（`plan: pro`），可使用全部功能。
   - **重置密码**：为团队用户设置新的登录密码（至少 6 位）。
   - **备注信息**：点击备注文字直接编辑（留空即清除），用于记录联系情况、续费备注等。
   - **订阅 / 续费申请**：团队账号在待办页顶栏提交的申请会显示为橙色的「**订阅申请**」/「**续费申请**」标记（含提交时间、**申请套餐**、联系方式、留言），且**该团队自动排到列表最前**（统计卡有「待处理订阅 / 续费申请」计数）；点「开通 / 续费」时会**自动按其申请套餐填入天数**，处理完成后标记**自动清除**。
   - **系统设置**（顶栏「**系统设置**」按钮）：
     - **网站名称**（登录页与页面标题，全局生效）；
     - **不允许新用户注册**：**默认不勾选（允许注册）**；勾选并保存后，**登录页不再显示「新帐户注册」按钮**，直接调用注册接口也会返回 403（已有账号登录不受影响，随时可取消勾选恢复注册）；
     - **忘记密码联系邮箱**：登录页显示的「忘记密码请联系 + 邮箱」，**默认 `support@cloudnexus.cn`**，可改成自己的客服邮箱；**留空则登录页不显示该提示**（填写时会校验邮箱格式）；
     - **网站图标链接（favicon）**：填入图片链接（`http://` 或 `https://` 开头）即可设置 / 修改浏览器标签页图标，输入框下方会**实时预览**；保存后**登录页 / 待办页 / 控制台**三个页面的标签页图标都会使用它（当前控制台标签页立即生效），**留空则恢复默认图标**；
     - **广告代码（试用版页面顶部的广告位）**：粘贴广告 **HTML / JS 片段**（≤3000 字符，如 `<a href="…"><img src="…"></a>` 或广告联盟代码），保存后**试用版（未订阅 / 订阅已到期）团队的待办页顶部**会插入该广告位；**团队订阅为专业版后自动移除**；**留空表示不插入广告**。
   - **邮件设置**（顶栏「**邮件设置**」按钮）：配置「注册邮箱确认码」的发件服务 ——
     **方式一（推荐）QQ 邮箱 SMTP**：**SMTP 账号**（完整 QQ 邮箱地址）、**SMTP 授权码**（16 位，**不是** QQ 登录密码）、
     SMTP 服务器（默认 `smtp.qq.com`）、端口（默认 `465`=SSL，`587`=STARTTLS，两者不通用时自动互试）；
     **方式二 Resend API**：**Resend API Key**（留空表示不修改、填 `-` 表示清除）；
     另有**发件邮箱地址**、**发件人名称**、**发送测试邮件**，以及**调试模式**（不真实发信，确认码直接显示在注册 / 登录页面，**仅供本地调试与演示**）。
     **环境变量优先于此处保存的配置**（见「部署步骤」）。
   - **订阅 / 续费申请邮件**（邮件设置里的独立分组）：团队账号在待办页提交「订阅申请 / 续费申请」时，
     系统会**自动发一封邮件给申请人（该团队的注册邮箱）**，并**抄送给管理员提醒邮箱**；邮件内容包含 ——
     **申请人信息**（团队名称 / 登录账号 / 联系人 / 联系邮箱 / 提交时间）、**订阅套餐信息**（申请类型 / 套餐与价格 / 天数 / 留言）、
     以及下面三项**可自定义的内容**（都在 `/admin` →「邮件设置」里维护）：
     - **管理员提醒邮箱**：抄送地址（**留空则默认抄送到「发件邮箱」**，也可用环境变量 `ADMIN_NOTIFY_EMAIL` 指定）；
     - **自定义文字说明**：最多 1000 字（如「请扫码支付后回复本邮件」「1 个工作日内开通」等，正文支持换行）；
     - **收款二维码图片链接 1 / 2 / 3**：最多 **3 个** `http://` 或 `https://` 开头的图片链接，会以 **180×180 的图片**插入邮件正文（留空则不显示该张）。
     发信结果会提示在提交弹窗里（成功 / 失败原因）；**邮件发送失败不影响申请提交**，控制台里仍会正常出现待处理的「订阅申请」标记。
   - **删除**（彻底删除团队用户）：**只有先「停用」的团队才会出现红色「删除」按钮**。
     点击后需**输入该团队的登录账号**二次确认，确认后会**永久删除**：该团队账号、其名下**全部成员 / 生产方 / 客户账号**，
     以及这些账号下的**所有订单（待办）、客户列表、生产方列表、备注与站内消息**（**不可恢复**）。
     删除完成后列表上方会提示本次删除的账号数与订单条数；其他团队与超级管理员不受影响。
   - **团队信息**：卡片中显示团队名称 / 登录账号 / **邮箱**（注册时必填；**尚未完成邮箱确认的团队会带橙色「未验证」标记**）/ 联系人 / 版本状态（试用账号（无期限）/ 专业版（剩余 N 天）/ 订阅已到期（试用）/ 已停用）/ 到期时间 / 注册时间 / 最近续费；搜索框支持按**团队名称 / 登录账号 / 邮箱 / 联系人 / 备注**模糊匹配。

### 🏭 生产方与「生产部 / 计划部 / 采购部 / 品质部 / 财务部」使用流程

> 说明：新增成员下拉中的 **生产部 / 计划部 / 采购部 / 品质部 / 财务部** 是**同一类角色**（`restricted`），**功能完全相同** —— 仅显示名称不同，可按实际部门建号。
> 其中 **品质部 / 财务部** 成员**不需要下生产单**：成员管理清单里不显示权限开关，权限固定为「无」（这两个部门只做只读查看与备注）。

1. **团队管理员**在顶部「生产方管理」中添加生产方（字段：**用户名**、**密码**、**生产方性质**（**手动输入**，最多 3 个中文字符或 6 个英文字符，如「自产」「外购」「代工」，默认「自产」）、**说明**；添加后会同时创建该生产方的登录账号）。
2. **团队管理员**在「成员管理」中新增成员时选择角色 **生产部 / 计划部 / 采购部 / 品质部 / 财务部** 之一；该成员下方会出现「可观察生产方」区块，可为其**添加 / 取消**授权的生产方（下拉选项来自「生产方管理」）。
3. **有权限的成员**（**权限5「是否可以更新订单状态」= 有**；团队账号本人已取消订单列表）**点击订单行最左侧的「状态」徽章**（就地从普通显示变为下拉）将某条待办的状态由「待确认」改为「**进行中**」时，会弹出「指定生产方」窗口，**必须选择**一个生产方（选项同样来自「生产方管理」）；选择完成后待办卡片上会显示该生产方的**简称**标签（鼠标悬浮可见完整含义）。
4. 该成员登录后，**只能看到其被授权生产方的（进行中/已完成）待办**（页面不再显示「你被授权的可观察生产方：xxx」提示栏）。

### 🏢 客户与成员使用流程

1. **团队管理员**在顶部「**客户管理**」中添加客户（字段：**用户名**、**密码**、**说明**；添加后会同时创建该客户的登录账号）。
2. **团队管理员**在「成员管理」中为某个**成员**分配客户：该成员下方「**可录入订单客户列表**」区块的下拉选项**直接来自「客户管理」**，选中后点「添加客户」即可（已分配的客户不会重复出现；全部客户都已分配时下拉会隐藏）。**该成员有客户后，登录即会显示「添加新订单」录入区**（权限1 自动生效；**该列表只决定能否录入订单**）；**没有客户时**权限1 显示为**「无」**（不显示录入区、也不能录入）。该成员能看到的订单范围由**新权限「是否可查看全部订单」**决定（**默认「是」**：可查看本团队全部订单，他人订单只读、可备注；选「否」：只能查看自己录入的订单 + 下方「**可查看客户列表**」中客户的订单，该列表为空则只能看自己的订单）。
3. 该成员登录后，在录入框的「客户」下拉中即可直接选用这些客户（下单选客户是录入待办的前置条件之一）。

### 🔔 站内消息（备注 @提及）

1. 打开任意待办的**下拉详情**，在「添加备注」输入框里输入 **`@`**（可继续输入用户名前缀过滤，如 `@zhang`）；
2. 弹出**本团队人员候选**（本团队各成员，**不含团队管理员账号、也不含自己**；生产方 / 客户属外部账号，不参与）：
   可用 **↑ ↓** 切换、**Enter / Tab** 选中，或直接**鼠标点击**；
3. 选中后输入框自动插入 **`@用户名 `**（如 `@zhangsan 请确认交期`），可继续输入文字，也可 @ 多个人；
4. 点「添加备注」提交后：
   - 被 @ 的成员收到一条**站内消息**：其页面**顶栏登录名左侧**出现角标；
   - 角标数字 = **未读** @ 次数，**超过 9 显示「9+」**（**红色**）；
   - **未读为 0 但仍有历史提醒时，角标显示为灰色「0」**（点击仍可查看历史提醒，不会因为已读而再也打不开）；
   - 从未收到过提醒时不显示角标；
   - 备注正文里的 `@用户名` 会**高亮显示**（浅蓝色标签）；
5. 点红点 → 弹出「**站内消息（@我的）**」面板：每条抬头一行显示 **谁 @ 了你 ＋ 时间 ＋ 在「待办名」对你说：**，下一行是**备注内容**
   （如「张三 2026-09-18 15:10 在「PO-L1」对你说：」＋备注内容）；**备注内容最多显示 60 字节**（UTF-8：ASCII 1 字节 / 中文 3 字节），
   超出则截断为前 60 字节并以 `...` 结尾（点该条即展开待办，可查看完整备注）；未读条目带浅红底；
   - **点某条消息**：该条即**标记为已读**、**未读提醒数 −1**（顶栏红点同步减少），随后**关闭消息面板**并**自动展开对应的待办**；
   - 每条消息**右上角有「未读」勾选框**：**勾选 = 把该条重新标记为未读**（顶栏红点数量 **+1**、未读底色恢复）；**取消勾选 = 标记为已读**（红点 **−1**）；
   - 面板内**没有「全部标记为已读」按钮**（改为逐条点击 / 勾选控制；如需一次性全部已读，可用接口 `POST /api/mentions/read` 不带 `id`）；
6. **专业版团队账号**在「成员管理」中也能看到**每位成员登录名左侧的红点**（该成员还有几条未读 @ 消息），便于跟进；
7. 顶栏红点在页面加载时显示，并**每 60 秒自动刷新**一次（别人新 @ 你的消息最迟 1 分钟内出现）。

> 说明：
> - 只有**本团队成员**能被 @ 到（**团队管理员账号不再出现在 @ 列表中**，写 `@团队账号` 也不会产生提醒）；**@ 自己**、**@ 不存在的用户名** 都不产生提醒；
> - 同一条备注里重复 @ 同一人**只记 1 条**；每位用户最多保留 **50 条**提醒（超出自动丢弃最早的）；
> - 删除成员时会同时清理其站内消息；**生产方 / 客户账号不参与** @提醒（在备注里写了他们的用户名也只会当普通文字，服务端不会校验通过）；
> - 相关接口：`GET /api/team-members`（可 @ 人员）、`GET /api/mentions`（我的消息 + 未读条数 + 总条数）、`POST /api/mentions/read`（带 `id` → 该条标记已读；带 `id` + `read:false` → 该条重新标记未读；不带 `id` → 全部标记已读；统一返回最新 `unread` / `total`）；`GET /api/me` 也会返回 `mentionsUnread`（未读数）与 `mentionsTotal`（总条数，用于未读为 0 时显示灰色「0」角标）；备注提交接口 `POST /api/todos/<待办id>/notes` 新增 `mentions` 字段（服务端同时会从备注文本里解析 `@用户名` 并校验是否为团队成员）。

### 📊 待办状态说明
待办共有三种状态，**新建待办默认为「待确认」**：

| 状态 | 说明 | 可见范围 |
| ---- | ---- | ---- |
| 🟠 待确认（pending） | 新建待办的默认状态 | 仅 **总经理 / 部门主管（历史账号）**、**权限5 成员** 和 **录入者本人** 可见 |
| 🔵 进行中（doing） | 由有权限的成员（权限5）确认后进入 | 本团队内所有人可见（含业务主管） |
| 🟢 已完成（done） | 由有权限的成员（权限5）标记完成 | 本团队内所有人可见（含业务主管） |

> 🔎 **列表默认只显示「进行中」（重要）**：订单列表上方的**筛选行**默认「**全部客户 + 进行中**」——
> 即默认视图只显示「各角色授权可见订单中状态为『进行中』的订单」；需要查看「待确认 / 已完成 / 全部状态」的订单时，
> 在「状态」下拉中选择对应状态（也可同时按「客户」筛选，两项可单选或双选），点「重置」恢复默认。
>
> **状态流转（显示形式）**：**订单行最左侧的「状态」一律按普通徽章样式显示**（🟠 待确认 / 🔵 进行中 / 🟢 已完成，**不再是下拉菜单**）—— 有权限的用户（**总经理（历史账号）/ 权限5「是否可以更新订单状态」= 是 的成员**）**点击该徽章**即就地变为下拉选择，选好立即保存并恢复为普通徽章（失焦未改则原样换回）；⚠️ 权限5 成员**只能改变自己清单里可见订单的状态**（可见范围仍由「是否可查看全部订单 / 可查看客户列表」决定，权限5 不扩大可见范围）；**部门主管 / 普通成员 / 观察类角色**的状态徽章为**只读**（点击无反应）。录入者新建的待办默认「待确认」，待被改为「进行中」后，业务主管才能看到。**⚠️ 团队账号本人（团队管理员）已取消订单列表**（首页为「系统介绍 + 使用说明」），订单状态一律由上述成员流转。
>
> **团队管理员**：**不再提供订单列表功能**（登录后首页为「系统介绍 + 使用说明」，按试用版 / 订阅版分别展示）—— 请通过「成员管理」把订单流转交给成员：为需要流转订单的成员开通**权限5「是否可以更新订单状态」**，该成员即可在自己可见的订单范围内改变状态、指定生产方、修改「待确认」订单、删除订单、添加备注（等同于团队管理员原先的能力）。**总经理（历史账号）**：待办列表显示**本团队**所有用户的待办（标注所有者），可**点击任意待办的「状态」徽章**改变其状态，也可删除任意待办；**固定不录入订单**。
>
> **部门主管**：同样显示**本团队**所有用户的待办（标注所有者），可**指定生产方**、修改「待确认」待办的 PO#/交期/金额/文件链接、**删除**待办、添加备注；但**订单状态为只读徽章，不能改变状态**；也**固定不录入订单**（列表上方无「添加新订单」录入区）。
>
> **「生产方」的显示时机与形式**：待办行左侧第二个「生产方」控件**仅在「待确认」阶段显示**（可预先指定）；「进行中 / 已完成」的待办以**灰色简称标签**展示生产方（如需修改生产方，先把状态改回「待确认」）。**显示形式**：待确认阶段的「生产方」**默认按普通文本标签显示**（**不再是下拉菜单**）—— 未指定时显示橙色「选择生产方」，已指定时显示生产方名称（悬浮可见完整含义与「点击更换」提示）；**有权限的用户（总经理 / 部门主管 / 权限5 成员）点击该标签**即就地变为下拉选择，选好立即保存并恢复为普通标签（失焦未改则原样换回）。由「待确认」改为「进行中」且未指定生产方时，会弹出「指定生产方」窗口强制选择。**注**：**试用团队 / 订阅已到期**的团队同样有「生产方管理」（试用版最多 1 个），**尚未添加任何生产方**时改为「进行中」**不会弹出**该窗口，可直接改为「进行中」（列表上会给出「点击顶部「生产方管理」添加」的提示）；**已添加生产方 / 专业版有效期内必须先指定生产方**。
>
> **PO# / 交期 / 金额 / 订单链接的修改**：仅「**待确认**」的待办可修改 —— **总经理 / 部门主管（历史账号）与权限5 成员**直接点击卡片上的**交期**或**金额**标签（可点击的标签带浅色描边、悬浮变蓝），在弹窗里同时修改 **PO#（主题）/ 交期 / 金额 / 订单文件链接**（链接可留空以清除）；状态进入「进行中 / 已完成」后不可再改。⚠️ **团队账号本人已取消订单列表**（首页为「系统介绍 + 使用说明」），因此该操作现由上述成员完成。
>
> **订单 / 采购文件链接**：**订单文件链接**在录入订单时填写（须以 `http://` 或 `https://` 开头，可留空）；**采购文件链接不在录入表单里填写**，改为录入后在订单行上补填（见下）。
> - **订单文件链接**：**生产方 / 客户**的列表里，PO# 会显示为链接，点击在新标签页打开该订单文件（不会触发展开/折叠）；**普通成员**按权限2「是否可以查看客户订单」或权限5「是否可以更新订单状态」（**两者默认均为「无」**）显示为链接；**部门主管**（历史账号）按「是否可查看客户订单」开关（默认「是」）。⚠️ **团队账号本人已取消订单列表**，不再出现在该说明中。
> - **采购文件链接（补填）**：订单行右端的「**生产方用户名·性质**」标签（如「张三·自产」）——**未填写**采购文件链接时显示为**黄色色块**，权限3「是否可以下生产订单 = 有」的成员（**权限5「是否可以更新订单状态」= 有** 的成员等同于已授权；普通成员由团队管理员在「成员管理」中逐个开关，**默认「无」**）点击可弹窗补填（不限订单状态，只能补当前为空的链接）；**已填写**时为**灰色**，**总经理（历史账号）固定可看 / 部门主管**（历史账号，按「是否可查看采购订单」开关，默认「是」）及权限4「是否可以查看生产订单 = 有」（或权限5 = 有）的普通成员点击即在新标签页打开该采购文件。
> - **脱敏订单文件链接（订单号右侧的「回形针」）**：**所有登录用户**都能看到该图标 —— **已填写**链接时图标**正常着色（蓝色）**，点击即在新标签页打开该**脱敏订单文件**（此时**只用于打开，不能再添加 / 修改**）；**未填写**时为**浅灰色**，权限6「是否可以下脱敏订单 = 是」的成员（普通成员由团队管理员在「成员管理」中逐个开关，**默认「无」**；⚠️ 权限5 不含该权限）点击可弹窗补填（不限订单状态，只能补当前为空的链接），**无该权限的用户**点击无反应（仅作提示）。
> - **出货日期（「交期」右侧的灰色区块，长度与交期一致）**：**所有登录用户**都能看到该区块 —— **已填写**时区块内显示**出货日期**（**不能再被点击重复添加**）；**未填写**时为**灰色空白区块**，权限7「是否可以添加出货日期 = 是」的成员（普通成员由团队管理员在「成员管理」中逐个开关，**默认「无」**；⚠️ 权限5 不含该权限）点击可弹窗选择日期并保存（不限订单状态，只能为当前为空的订单添加），**无该权限的用户不能点击**（区块仅作占位显示）。
> - **业务主管 / 生产部**：列表里 PO# 一律为纯文本，不可点击。
>
> **普通成员**：可见范围由**自动**权限「是否可查看全部订单」决定 —— **默认「是」**（可查看**本团队全部订单**（含待确认）；他人录入的订单为只读徽章，不可改状态 / 不可删除，但**可添加备注**）；当管理员在「**可查看客户列表**」中为该成员**选择了 N 个客户**后，自动变为「**否（可查看 N 个客户）**」：**只能看到自己录入的待办 + 这 N 个客户的订单**（这些他人订单同样是只读徽章、可添加备注）。⚠️ **权限5「是否可以更新订单状态」= 是 不会改变这里的可见范围** —— 只是在上述范围内额外获得改状态 / 指定生产方 / 修改待确认订单 / 删除的能力。「可录入订单客户列表」里**有客户**才显示「添加新订单」录入区（**该列表只决定能否录入订单**，与可见范围无关）。
>
> **业务主管**：待办列表显示**本团队**用户**非待确认**的待办（标注所有者），添加框与删除按钮均隐藏、**状态为只读徽章**（不可改变状态），但可在任意待办下添加备注。
>
> **备注规则**：所有用户（含业务主管）均可添加备注，备注为追加式，记录作者与时间，添加后不可删除。
>
> **交期配色**：**待确认 / 进行中 / 已完成**三种状态的待办**使用同一套交期配色** —— 当前日期 **≥ 交期**（已到期/逾期）显示**红色**；剩余 **0~2 周**（1~14 天）显示**黄色**；剩余**超过 2 周**（>14 天）显示**绿色**。

## 🚀 部署步骤

### 1. 安装依赖

```bash
npm install
```

### 2. 登录 Cloudflare

```bash
npx wrangler login
```

### 3. 创建 KV 命名空间

```bash
npx wrangler kv:namespace create TODO_KV
```

命令会输出类似：

```
[[kv_namespaces]]
binding = "TODO_KV"
id = "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

将输出的 `id` 复制到 `wrangler.toml` 中替换 `REPLACE_WITH_YOUR_KV_NAMESPACE_ID`。

### 4. 配置邮件发送（注册邮箱确认码，必须）

团队账号注册需要向「注册时填写的邮箱」发送 **6 位确认码**，因此**必须先配置发件服务**（三种方式任选其一）：

**方式 A：QQ 邮箱（SMTP + 授权码，推荐）**

1. 用网页版登录 QQ 邮箱 → 右上角「**设置**」→「**账户**」→ 找到「**POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务**」→
   开启「**POP3/SMTP服务**」（按提示用手机发送短信验证）→ **生成授权码**（16 位字母，**注意：不是 QQ 登录密码**）；
2. 填入本项目（任选其一）：

```bash
# ① 存为 Worker 密钥（推荐，线上生效）
npx wrangler secret put SMTP_USER    # 完整 QQ 邮箱地址，如 123456789@qq.com
npx wrangler secret put SMTP_PASS    # 上一步生成的 16 位授权码
npx wrangler secret put MAIL_FROM_NAME   # 发件人名称（可选），如 订单管理系统
```

> 也可以用 `QQ_MAIL_USER` / `QQ_MAIL_PASS` 作为变量名（等价）。
> 默认服务器 `smtp.qq.com:465`（SSL）；如需 587 端口，设置 `SMTP_PORT=587`（自动走 STARTTLS）。
> **未配置 `MAIL_FROM` 时，发件邮箱自动取 SMTP 账号**（QQ 邮箱要求发件地址与登录账号一致）。

**② 或在管理界面里配置**：用 `admin / admin` 登录 `/admin` → 顶栏「**邮件设置**」→ 填 **SMTP 账号 + SMTP 授权码**
（服务器/端口可留默认）→ 「保存」→ 再点「**发送测试邮件**」验证。
界面里填的配置保存在 KV（`emailSettings`），**环境变量优先于界面配置**，界面会显示当前配置来源。

**方式 B：Resend API**

1. 到 [resend.com](https://resend.com) 注册并**验证发件域名**，创建 **API Key**；
2. `npx wrangler secret put RESEND_API_KEY`（配合 `MAIL_FROM` / `MAIL_FROM_NAME`），或在 `/admin`「邮件设置」中填写。

**方式 C：Cloudflare Email Routing（`send_email` 绑定，无需账号密码）**

发件域名已在 Cloudflare 托管并启用 Email Routing 时，在 `wrangler.toml` 中增加绑定：

```toml
[[send_email]]
name = "SEND_EMAIL"
```

**调试模式（不真实发信）**：若暂时不想接入邮件服务，可登录 `/admin` → 「邮件设置」→ 勾选「**调试模式**」，
此时注册 / 登录所需的确认码会**直接显示在页面上**（注册页会显示「调试确认码：123456」），便于本地调试与演示。
**正式环境请勿开启**。此外，本地 `npm run dev` 访问 `http://localhost:8787` 时若未配置邮件服务，
会自动按调试模式处理（页面直接显示确认码）。

> ✅ **SMTP 的 TLS / STARTTLS 说明（已实测）**：本地 `wrangler dev` 与线上 Cloudflare **都能**真实发送 SMTP 邮件，
> 关键实现细节（修改代码时请勿破坏）：
> - `connect()` 的 `secureTransport` **必须作为第二个参数（SocketOptions）传入**：
>   `connect({ hostname, port }, { secureTransport: "on" | "starttls" })`。
>   若把它写进第一个「地址对象」里会被运行时忽略（默认 `off`）→ 465 变成明文连接（对端等 TLS 握手 → 超时无响应）、
>   587 调用 `startTls()` 直接抛 `The secureTransport socket option must be set to 'starttls' ...`。
> - 465 用 `secureTransport: "on"`（隐式 SSL）；587 用 `secureTransport: "starttls"`，发完 `STARTTLS` 后
>   必须先 `releaseLock()` 释放旧 `reader` / `writer`，再 `socket.startTls()` 并重新取新的读写流，
>   否则会报 `This WritableStream is currently locked to a writer`。
> - 仅 **25 端口**被 Cloudflare 禁止，465 / 587 均可用；`startTls()` 只能调用一次。
>
> 实测记录（本地 `wrangler dev` 直连真实 `smtp.qq.com`，用无效授权码）：465 与 587 都能完成握手与会话，
> 返回 QQ 的 `535 Login fail ...`（即失败原因只剩「授权码 / 账号」本身）。
>
> - 本地开发若不想联网发信：可勾选「**邮件设置 → 调试模式**」（确认码直接显示在页面上）；
> - 真实验证发信：在 `/admin` →「邮件设置」→「**发送测试邮件**」。
> - 失败时会**逐端口汇总原因**并给出指引，例如：
>   `端口 465：…连接或响应超时（8 秒）…；端口 587：…（提示：QQ 邮箱必须使用「SMTP 授权码」…）`
>
> 💡 **端口自动回退**：代码会先按配置端口发送，失败时自动改另一个端口（465 ⇄ 587）重试一次，
> 因此 465 / 587 只需填对账号与授权码即可，无需手动判断。

### 7. 方式二：手动上传（不用命令行）

适合不想装 wrangler / 没有本地 Node 环境，直接在 Cloudflare 控制台里粘贴代码的情况。

> ⚠️ **采用本方式时，每次改完代码都必须重新构建一次 `dist/worker.js`** ——
> 否则控制台里粘贴的仍是**旧产物**，表现就是「明明改了代码、页面却没有任何变化」
> （例如权限设置里还是旧的勾选框、看不到新增的客户列表区块等）。
> 重新构建后**必须重新粘贴一次**并 `Save and Deploy`；浏览器端请**强制刷新**（`Ctrl/Cmd + Shift + R`）后查看。

**① 把两个源文件压成一个文件**（控制台编辑器只接受单文件）：

```bash
npm run build:dist
```

（等价命令：`npx --yes esbuild@0.24.0 src/index.js --bundle --format=esm --target=es2022 --minify --charset=utf8 --legal-comments=none --external:cloudflare:sockets --outfile=dist/worker.js`）

生成 `dist/worker.js`（约 280KB，单文件 ES Module；`--charset=utf8` 保留中文不转义，否则体积会翻倍；
`--external:cloudflare:sockets` 必须保留 —— QQ 邮箱 SMTP 发信要用 Workers 内置的 TCP Socket 模块）。

> 🔍 **上传前可自查产物是否为目标版本**（在 `dist/worker.js` 里搜索关键字）：
> 应能搜到「**可查看客户列表**」「**view-customers**」，且**搜不到**「**data-canviewallorders**」
> （后者是旧版「是否可查看全部订单」勾选框的痕迹，搜到说明产物是旧的）。

**② 控制台创建 KV 命名空间**：`Storage & Databases` → `KV` → `Create namespace`（名称如 `TODOLIST_KV`）→ 记下 **Namespace ID**。

**③ 创建 Worker**：`Workers & Pages` → `Create` → `Worker` → 起个名字（如 `cf-todolist`）→ `Deploy`。

**④ 粘贴代码**：进入该 Worker → `Edit code` → 全选删除 → 粘贴 `dist/worker.js` **全部内容** → `Save and Deploy`。

**⑤ 绑定 KV（必须做，否则报错）**：Worker → `Settings` → `Bindings` → `Add binding` → **KV Namespace** →
- Variable name 必须是 **`TODO_KV`**（要和代码里的 `env.TODO_KV` 一致）
- KV namespace 选第 ② 步创建的那个 → `Save`（会重新部署）

**⑥ 访问** `https://cf-todolist.<你的子域>.workers.dev`，用 `admin` / `admin` 登录（超级管理员）并**立刻改密码**。

**⑦ 配置邮件发送（注册确认码，必须）**：控制台无法设置 `[vars]`/secret 时，可任选其一：
- `Workers & Pages` → 你的 Worker → `Settings` → **Variables and Secrets** → 新增 Secret `SMTP_PASS`（QQ 邮箱授权码）
  以及变量 `SMTP_USER`（QQ 邮箱地址）/ `MAIL_FROM_NAME` → `Save and Deploy`；
- 或直接登录 `/admin` → 顶栏「**邮件设置**」填写 **SMTP 账号 + SMTP 授权码** 并保存（无需命令行）。

> 以后更新：重新执行 ① 生成 `dist/worker.js` → 回到 ④ 粘贴覆盖 → `Save and Deploy`。
> ❗ 未配置邮件服务（且未开启调试模式）时，团队账号注册会失败并提示联系超级管理员配置发件服务。

## 🗂️ 数据存储说明

所有数据存储在 Cloudflare KV 中，键结构如下：

| Key                | 说明                     |
| ------------------ | ------------------------ |
| `user:<用户名>`    | 用户信息（密码哈希、`role`、`teamId`（所属团队）、成员备注 `remark`、**职位 `position`**（新增成员时由团队管理员手动填写，成员列表中点击职位文字即可修改）、**所属部门 `dept`**（仅「生产部 / 计划部 / 采购部 / 品质部 / 财务部」这 5 个 `restricted` 角色的成员有值，用于显示具体部门名）、权限开关 `canPlaceOrder`（历史字段；**普通成员（原业务部）的权限1「添加订单」由「是否已分配客户」自动决定**，该字段不再参与判断；品质部 / 财务部成员固定按「无」处理；**团队账号本人**：试用账号可录入订单、**专业版不录入订单**，由成员录入，接口同样拦截）、权限3「是否可以下生产订单」`canPurchase`（普通成员**默认「无」**，由团队管理员在「成员管理」的成员列表中逐个开关；历史角色未设置过时与其 `canPlaceOrder` 一致，保证历史行为不变）、权限2「是否可以查看客户订单」`canViewCustomerOrder`（普通成员**默认「无」**，由团队管理员在成员列表中逐个开关；部门主管历史账号未设置过默认「是」）/ 权限4「是否可以查看生产订单」`canViewPurchaseOrder`（普通成员**默认「无」**；部门主管历史账号未设置过默认「是」）/ 权限5「是否可以更新订单状态」`canUpdateStatus`（普通成员**默认「否」**，= 是 时订单列表显示与功能与团队管理员相同：可见全部订单、可改状态 / 指定生产方 / 修改待确认订单 / 删除 / 备注，订单号与「自产单 / 外购单」标签可点击）、新权限「是否可查看全部订单」`canViewAllOrders`（普通成员**默认「是」**：可查看本团队全部订单，他人订单只读、可备注；`false` = 只能查看自己录入的订单；**与 `customers:<用户名>`（客户列表）无关** —— 客户列表只决定权限1「添加订单」是否生效）、**权限6「是否可以下脱敏订单」`canPlaceMaskedOrder`**（普通成员**默认「无」**：= 是 时可点击订单列表中**订单号右侧灰色的「回形针」**添加**脱敏订单文件链接**（写入该待办的 `maskedUrl`，已有值不可再改；详见 `todos:` 行））、**权限7「是否可以添加出货日期」`canAddShipDate`**（普通成员**默认「无」**：= 是 时可点击订单行**「交期」右侧的灰色空白区块**添加**出货日期**（写入该待办的 `shipDate`，已有值不可再改；详见 `todos:` 行）））；**团队用户**另有 `teamName` / `email`（注册时必填的邮箱）/ **`emailVerified`**（`false`=注册邮箱尚未用确认码确认，**未确认前不允许登录**；`true` 或**无该字段**（升级前的历史账号）=已确认）/ `emailVerifiedAt` / `plan`（`trial`=无限期试用、`pro`=专业版，历史数据 `paid` 同样按专业版处理）/ `status` / `trialEndsAt` / `expiresAt` / `subscribeRequest`（订阅 / 续费申请：`at` / `kind`（`subscribe`=订阅、`renew`=续费）/ `plan`（`id` / `term` / `price` / `days`）/ `note` / `contact`）等字段；**生产方 / 客户登录账号**同样是该结构（`role: "producer"` + `producerId`，或 `role: "customer"` + `customerId` / `customerName`） |
| `emailcode:<用户名>` | 该账号**尚未使用的注册邮箱确认码**（JSON：`codeHash`（**只存哈希，不存明文**）/ `email` / `sentAt` / `attempts`；**10 分钟自动过期**，确认通过后立即删除，连错 5 次也会删除） |
| `mailrate:<用户名>` | 确认码发送频率记录（JSON：`windowStart` / `count` / `lastSentAt`；**1 分钟内不重复发送、1 小时最多 5 次**，1 小时后自动过期） |
| `emailSettings`    | 邮件发件服务配置（JSON：`smtpHost` / `smtpPort`（QQ 邮箱默认 `smtp.qq.com:465`）/ `smtpUser`（QQ 邮箱地址）/ `smtpPass`（**SMTP 授权码**）/ `apiKey`（Resend API Key）/ `from` / `fromName` / `devMode`（调试模式）/ **`adminNotifyEmail`（订阅申请邮件抄送给管理员的提醒邮箱，留空默认用发件邮箱）** / **`subExtraText`（订阅申请邮件的自定义文字说明，≤1000 字）** / **`subQrCodes`（订阅申请邮件里的收款二维码图片链接数组，最多 3 个）**）；仅超级管理员可读写，**环境变量 `SMTP_USER` / `SMTP_PASS`（或 `QQ_MAIL_USER` / `QQ_MAIL_PASS`）/ `SMTP_HOST` / `SMTP_PORT` / `RESEND_API_KEY` / `MAIL_FROM` / `MAIL_FROM_NAME` / `ADMIN_NOTIFY_EMAIL` 优先于这里的配置** |
| `session:<token>`  | 登录会话（7 天过期）     |
| `todos:<用户名>`   | 该用户的待办列表（JSON；按 `teamId` 归属团队）。每条待办的字段：`id` / `customer` / `title`（PO#）/ `dueDate` / `amount` / `currency`（`USD` / `CNY`）/ **`orderUrl`**（订单文件链接）/ **`purchaseUrl`**（采购文件链接）/ **`maskedUrl`**（**脱敏订单文件链接**：订单号右侧的「回形针」） / **`shipDate`**（**出货日期**：`yyyy-mm-dd`，「交期」右侧的灰色区块） / `notes` / `status`（`pending` / `doing` / `done`）/ `done` / `createdAt` / `producerId` / `producerName` / `producerAssignedAt`；**`maskedUrl` 由权限6「是否可以下脱敏订单」= 有 的成员通过 `POST /api/todos/<id>/masked-link` 一次性写入（已有值不可再改）**；**`shipDate` 由权限7「是否可以添加出货日期」= 有 的成员通过 `POST /api/todos/<id>/ship-date` 一次性写入（已有值不可再改）** |
| `customers:<用户名>` | 该成员的「**可录入订单客户列表**」（JSON；决定该成员能否录入订单） |
| `viewCustomers:<用户名>` | 该成员的「**可查看客户列表**」（JSON；**同时决定自动权限「是否可查看全部订单」**：列表为空 = 是（可查看本团队全部订单）；选择了 N 个客户 = 否（只能查看这 N 个客户的订单 + 自己录入的订单）。由团队管理员在「成员管理」中维护，成员记录上的 `canViewAllOrders` 会随之自动同步） |
| `watch:<用户名>`   | 「生产部 / 计划部 / 采购部 / 品质部 / 财务部」成员「可观察生产方」的 id 列表（JSON） |
| `mentions:<用户名>` | 该用户的**站内消息**（被 @ 的提醒记录 JSON，最新在前：`from` / `todoId` / `todoTitle` / `todoOwner` / `text` / `at` / `read`；最多保留 50 条） |
| `producers:<团队id>` | 该团队的生产方列表（用户名 + 说明，JSON）；对应的登录账号见 `user:<用户名>` |
| `customerList:<团队id>` | 该团队的客户列表（用户名 + 说明，JSON）；供「客户管理」与成员分配使用 |
| `orderProducers:<用户名>` | 该成员的「**可选生产方**」授权列表（生产方 id 数组 JSON；**默认「无」= 无该键**）—— 授权后该成员录单时可在「生产方选择」下拉中指定这些生产方；由团队管理员在「成员管理 → 可选生产方列表」中维护（`/api/order-producers/`） |
| `settings`         | 全局设置（网站名称 `siteName`；**是否允许新用户注册 `allowRegister`**：`false`=关闭注册，**未设置或 `true`=允许**；**忘记密码联系邮箱 `supportEmail`**：未设置时默认 `support@cloudnexus.cn`，**空字符串=登录页不显示该提示**；**网站图标 `favicon`**：图片链接（http/https），空=默认图标；**试用版广告代码 `adCode`**：HTML / JS 片段（≤3000 字符），会插入试用版（未订阅）待办页顶部的广告位，订阅专业版后不再显示，空=不插入；均仅超级管理员可改） |

> 团队 id 即「团队用户」的登录用户名；历史数据没有 `teamId`，读取时归入默认团队 `default`
> （对应的旧 key 就是 `producers` / `customerList`，代码已做兼容）。
>
> 🗑️ **彻底删除团队时**：会按 `teamId` 找出该团队下的**全部账号**（团队用户本人 + 成员 + 生产方 + 客户），
> 逐个删除其 `user:` / `todos:` / `customers:` / `watch:` / `mentions:` / `emailcode:` / `mailrate:`，
> 并删除团队级 `producers:<团队id>` 与 `customerList:<团队id>`；**其他团队与超级管理员的数据不受影响**。

- 密码使用 SHA-256 加盐哈希存储，不保存明文。
- **注册邮箱确认码**也只保存**哈希**（`emailcode:<用户名>`，10 分钟过期）；验证通过后立即删除，不会长期留存。
- 会话通过 HttpOnly Cookie 保存，有效期 7 天。

## 🔧 自定义

- **修改超级管理员（admin）密码**：登录后通过界面修改即可。
- **试用期限**：新注册团队账号为**无限期试用**（无到期时间），无需配置；试用期间**功能与专业版基本相同**，仅**数量受限**（成员最多 2 个 / 生产方最多 1 个 / 客户最多 1 个）且**页面顶部显示广告位**，订阅后成为专业版：**数量限制解除 + 广告位移除**。
- **修改订阅套餐 / 价格**：编辑待办页（`src/pages.js` 的 `todoPage()`）中的 `SUBSCRIBE_PLANS`（套餐 id / 名称 / 价格 / 顺延天数）；超级管理员控制台的快捷天数按钮在同文件 `adminPage()` 的续费弹窗中。
- **修改会话有效期**：编辑 `src/index.js` 中的 `expirationTtl` 和 `Max-Age`。
- **修改注册邮箱确认码规则**：编辑 `src/index.js` 顶部的 `CODE_TTL_SEC`（有效期，默认 10 分钟）、
  `CODE_RESEND_SEC`（重发间隔，默认 60 秒）、`CODE_MAX_PER_HOUR`（每小时最多发送次数，默认 5）、
  `CODE_MAX_ATTEMPTS`（最多输错次数，默认 5）。
- **修改确认码邮件内容**：编辑 `src/index.js` 的 `verifyCodeMailBody()`（主题 / 纯文本 / HTML）。
- **更换 / 调整发件服务**：编辑 `src/index.js` 的 `getMailConfig()`（默认 `SMTP_HOST=smtp.qq.com`、`SMTP_PORT=465`）
  与 `sendMail()`（当前支持 **QQ 邮箱等 SMTP 发信**、**Resend HTTP API**、**Cloudflare `send_email` 绑定**）；
  SMTP 服务器 / 端口、账号、授权码都可以在 `/admin` →「邮件设置」里改，或用环境变量覆盖。
- **修改端口/名称**：编辑 `wrangler.toml` 中的 `name`。

## 📌 注意事项

- Cloudflare KV 免费额度：每天 10 万次读、1000 次写。个人使用完全够用。
- KV 为最终一致性存储，写入后可能有短暂延迟（通常 < 60 秒），对本应用无影响。
- **团队被停用后**：该团队账号及其所有成员（含生产方、客户）都会立即无法访问（每次请求都会校验团队状态），重新「开通」后即可恢复。
- **彻底删除团队不可恢复**：需先「停用」该团队（列表中才会出现红色「删除」按钮），并在弹窗中**输入该团队的登录账号**二次确认；
  确认后会永久删除该团队账号、其名下全部成员 / 生产方 / 客户账号，以及这些账号的**所有订单（待办）、客户列表、生产方列表、备注与站内消息**。
  **删除前请先自行备份需要保留的数据**（例如导出订单），操作后无法找回。
- **新用户注册开关**：超级管理员在 `/admin` →「**系统设置**」中勾选「**不允许新用户注册**」即可关闭注册 ——
  **登录页不再显示「新帐户注册」按钮**（也不会渲染注册表单），且**直接调用 `/api/register` 会被拒绝**（403）。
  **默认不勾选（允许注册）**；关闭期间已有账号登录、使用均不受影响，取消勾选保存后立即恢复注册入口。
- **试用 / 订阅到期**：试用账号为**无限期试用**（不会到期），**功能与专业版基本相同**，仅保留数量限制（**成员 2 个 / 生产方 1 个 / 客户 1 个**）并在**页面顶部显示广告位**，**团队账号本人同样不录入订单**（订单由成员录入）；**专业版订阅到期后不会锁定账号**，而是自动**回落为同一「试用（受限）」状态** —— 仍可登录、可添加成员 / 生产方 / 客户（受数量限制）且页面顶部重新出现广告位，需重新「订阅」并由超级管理员开通后解除数量限制并移除广告。
- **数据归属**：成员 / 生产方 / 客户 / 待办 / 团队内的生产方与客户列表都按 `teamId` 隔离，删除成员不会影响其他团队。
- **历史数据**：升级前的老数据（无 `teamId`）归入默认团队 `default`，不会自动删除，但不会出现在任何团队用户的界面里。
- **注册邮箱确认码（团队账号）**：注册后**必须用邮件中的 6 位确认码在登录页完成邮箱确认**才能正常登录；
  确认码 **10 分钟有效**、**连错 5 次即失效**；点「重新发送确认码」需填写该账号的登录密码，且**1 分钟内不重复发送、1 小时最多 5 次**。
  若「邮件设置」未配置且未开启调试模式，**注册会直接失败并自动回滚**（不会占用用户名），提示联系超级管理员配置发件服务；
  超级管理员可在 `/admin` → 「邮件设置」中配置 **QQ 邮箱 SMTP 账号 + 授权码**（或 Resend API Key），
  或临时开启**调试模式**先跑通流程。**成员 / 生产方 / 客户**账号由团队管理员创建，不走邮箱确认（无需邮箱）。
- **QQ 邮箱发信注意**：必须使用「**SMTP 授权码**」（在 QQ 邮箱「设置 → 账户」中开启 POP3/SMTP 服务后生成），
  **不是 QQ 登录密码**；且「发件邮箱」需与 SMTP 账号一致（未填发件邮箱时系统自动使用 SMTP 账号）。
  默认 `smtp.qq.com:465`（SSL）；若 465 不通会自动改用 587（STARTTLS）重试，并在报错里逐端口说明原因。
  **本地 `wrangler dev` 无法做 SMTP 的 TLS（3.x / 4.x 实测均如此），本地请用「调试模式」，真实发信请部署后验证。**
